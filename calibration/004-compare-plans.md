# Calibration pair 004 — compare plans

**ID:** `004-compare-plans`
**Scope:** channel: marketing · audience: business operators choosing a Bolt plan · purpose: compare options and pick a next step
**Status:** active
**Reference revision:** uncommitted draft (based on `fa96b34`)
**Reusable-direction approval:** Approved by Lillian on 2026-11-09 as reusable direction for the scope above.

**Baseline method:** informal. No clean-session agent baseline was run. "Original" is the team's earlier pricing page. "With the system" is Lillian's own approved rewrite, not an agent rewrite. Both are excerpts: only the contrasts Lillian named are shown, and the full page copy isn't reproduced.

## Original

> **Pricing**
>
> Start for free. No credit card required.
>
> Custom · billed by consumption
>
> ✓ Bolt branding

*Also in the original: filler lines in plan descriptions, the same fact repeated across plans, and a daily cap that wasn't named the way people hit it.*

## With the system

> **Explore plans**
>
> Start for free. Upgrade as you grow.
>
> Custom pricing · priced by usage

*Also in the rewrite: "Bolt branding" sits with a few honest cons in the entry plan, not as a checked benefit. Each plan leads with one short benefit, each bullet holds one benefit with the strongest differentiators first, and buttons use sentence case.*

## What drove the difference

| Change | Rule | File |
|---|---|---|
| "Pricing" → "Explore plans" | A headline invites a comparison or next step, not the page type | `../references/marketing.md` |
| "No credit card required" removed from the line above all plans | A line above every option must be true for every option; say each fact once | `../references/marketing.md` |
| "Custom" → "Custom pricing," "billed by consumption" → "priced by usage" | No buyer or procurement jargon | `../references/marketing.md`, `../references/voice.md` |
| No checkmark on "Bolt branding"; honest cons in the entry plan | Don't mark a limitation as a benefit; honest cons make paid options clearer (marketing exception to "Prefer positive phrasing") | `../references/marketing.md` |
| Filler cut; one benefit per bullet, strongest first | Lead each option with one short benefit | `../references/marketing.md` |
| Daily cap stated plainly | Name limits the way people will hit them | `../references/marketing.md` |
| Sentence-case buttons | Sentence case for UI-like marketing controls | `../references/channels.md`, `../references/style.md` |

## What this teaches

When people are choosing between options, tell them the truth about each one, including what the entry option doesn't do, so the differences are easy to see.

*Plan names, prices, limits, and value props are product facts from the page, not writing rules.*
